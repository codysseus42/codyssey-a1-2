# A1-2: LLM + 지도 API 국내 여행지 추천 CLI

여행 날짜를 입력하면 Gemini API(LLM)와 Kakao Local API(지도/장소)를 조합해 국내 여행 리포트를 생성하는 커맨드라인 프로그램입니다.

| 구분 | 내용 |
|---|---|
| LLM | Google Gemini (`gemini-3.6-flash`, 폴백 `gemini-3.5-flash`) |
| 지도/장소 | Kakao Local — 키워드 검색 |
| 입력 | `--date YYYY-MM-DD` |
| 출력 | 원본 JSON + 마크다운 리포트 (`results/`) |
| 의존성 | `requests`, `python-dotenv` |

---

## 동작 개요

```
--date 입력 → [1] Gemini 1차 추천(JSON) → [2] Kakao Local 맛집 검색 → [3] Gemini 최종 리포트(Markdown)
```

| 단계 | 하는 일 | 출력 |
|---|---|---|
| 1 | 해당 시기에 여행하기 좋은 국내 도시를 JSON으로 추천 | `recommended_city`, `weather`, `events`, `reason` |
| 2 | 1단계의 `recommended_city`로 맛집 5곳 검색 | `food_list` |
| 3 | 1·2단계 결과를 종합해 마크다운 리포트 생성 | `report` |

## API 키 설정 방법

1. `.env.example`을 복사해 `.env`를 만듭니다.

   ```bash
   cp .env.example .env
   ```

2. 아래 두 값을 채웁니다.

   | 키 | 발급처 |
   |---|---|
   | `GEMINI_API_KEY` | [Google AI Studio](https://aistudio.google.com/) |
   | `KAKAO_API_KEY` | [Kakao Developers](https://developers.kakao.com/) > 내 애플리케이션 > 앱 키 > **REST API 키** |

3. 선택 항목: `TEXT_MODEL`, `TEXT_MODEL_FALLBACK`, `BASE_URL`

키가 설정되지 않으면 **즉시 종료**하며, 어떤 키가 빠졌는지와 발급 방법을 안내합니다.

![키 미설정](./readImage/noKey.png)

### API 키 유출 방지

| 항목 | 조치 |
|---|---|
| 코드 내 하드코딩 | 없음. `os.getenv()`로만 읽음 |
| 저장소 커밋 | `.env`를 `.gitignore`에 등록 |
| 결과물 파일 | 외부 API의 에러 응답 본문을 저장하지 않고 **상태 코드만** 기록 |
| 진단 로그 | `*_error.json`, `*_warning.jsonl`을 `.gitignore`에 등록 |

Kakao는 401 응답 메시지에 요청에 사용된 앱 키를 그대로 되돌려줍니다. 개발 중 실제로 결과 파일에 키가 저장되는 것을 확인했고, 예외 메시지에서 응답 본문(`r.text`)을 제거해 해결했습니다.

## 입력 검증

`--date`는 argparse의 `type=` 검증 함수에서 처리합니다. 검증을 인자 정의에 붙여두면 `main()` 본문은 "날짜는 이미 유효하다"를 가정하고 시작할 수 있습니다.

| 조건 | 처리 |
|---|---|
| `YYYY-MM-DD` 형식 아님 | usage 출력 후 종료 |
| 오늘 이전 | usage 출력 후 종료 |
| 오늘 + 180일 초과 | usage 출력 후 종료 (정보 신뢰성 확보 불가) |

![날짜 검증](./readImage/date.png)

과거·원거리 미래 판정은 LLM이 아니라 로컬에서 처리합니다. 날짜 비교는 결정적인 연산이므로 API 호출을 쓸 이유가 없고, 잘못된 입력이 API 비용을 발생시키기 전에 걸러집니다.

## 에러 처리 정책

실패를 두 축으로 나눕니다 — **재시도 가능한가**와 **파이프라인을 중단하는가**. 두 축은 독립입니다.

| 상황 | 재시도 | 파이프라인 |
|---|---|---|
| API 키 미설정 | 불가 | **즉시 종료** |
| LLM JSON 파싱 실패 / 필수 키 누락 | **1회** (프롬프트 수정 후 재요청) | 재시도까지 실패하면 종료 |
| Gemini 429/500/503 | 폴백 모델로 1회 | 계속 |
| 지도 API 호출 실패 (인증·쿼터·서버 오류) | 불가 | **계속** — 맛집을 "데이터 없음"으로 표기 |
| 지도 API 검색 결과 0건 | 해당 없음 | 계속 |
| 맛집 항목 필수 필드 누락 | 해당 없음 | 해당 항목만 제외하고 계속 |

**키 미설정과 지도 API 401은 둘 다 재시도가 불가능하지만 처리가 정반대입니다.** 차이는 "그것 없이도 리포트를 만들 수 있는가"입니다. 키가 없으면 아무것도 못 하지만, 맛집이 없어도 도시·날씨·행사·일정은 나옵니다.

search_places()는 401·403(인증), 429(쿼터), 그 외 비200을 각각 다른 메시지로 구분해 사용자가 화면에서 바로 조치를 알 수 있게 합니다. 세 경우 모두 재시도하지 않고 파이프라인은 계속 진행하는데, 상태 코드에 따라 원인과 조치가 다르기 때문에 메시지는 나누고 흐름 제어는 통합했습니다.

### 재시도 프롬프트

JSON 파싱이나 필수 키 검증에 실패하면, 원래 프롬프트에 다음을 덧붙여 한 번만 재요청합니다.

```
이전 응답이 올바르지 않았습니다. 다음 키를 모두 포함한 JSON 객체 하나만 출력하세요:
recommended_city, weather, events, reason
```

필수 키 목록은 호출부가 `run_stage()`에 인자로 넘기므로 스테이지마다 다른 키를 요구할 수 있고, 재시도 문구에도 그 목록이 그대로 들어갑니다. 재시도 상한은 `for i in range(2)`로 코드에 고정되어 있어 무한 재시도가 발생하지 않습니다.

실제로 1차 추천에서 `events` 키가 누락되어 재요청이 발동한 사례를 확인했고, 두 번째 응답에서 정상 반환되었습니다.

두 번째 경우의 결과물이 [`2026-10-30_travel_plan.md`](./results/2026-10-30_travel_plan.md)입니다.

```markdown
## 맛집 추천
데이터 없음

## 1일 일정 제안
- 내장산 국립공원 붉은 단풍 터널 산책 및 산세 감상
...

## 오류 요약(errors)
- [restaurantRecommend] RuntimeError: 인증 실패(401). KAKAO_API_KEY 값과 Kakao Developers의 플랫폼/도메인 설정을 확인하세요

```

맛집 섹션은 "데이터 없음"으로 표기되고, 일정 제안은 식사 일정을 빼고 관광지 중심으로 재구성됩니다. 프롬프트에 "입력에 없는 사실을 새로 만들지 않는다"를 명시했기 때문에 존재하지 않는 맛집을 지어내지 않습니다.

### 실패 기록의 흐름

`errors`는 `main()`의 지역 변수로 만들어 `run_stage()`에 인자로 전달합니다. 실패한 자리가 자신이 아는 정확한 타입으로 기록하고, `main()`은 반환값이 `None`인지만 보고 흐름을 결정합니다. **기록은 실패 지점이, 판단은 호출부가** 담당합니다.

누적된 `errors`는 세 곳에 반영됩니다.

1. 터미널 출력
2. `{날짜}_raw_data.json`의 `errors` 필드
3. 최종 리포트 끝의 `## 오류 요약(errors)` 섹션

저장은 `finally` 블록에서 수행하므로, 정상 종료든 예외 종료든 원본 JSON이 남습니다.

오류 요약 섹션은 LLM이 아니라 **코드가 직접 렌더링합니다.** 오류 기록은 사실이므로 요약되거나 윤색되면 디버깅 정보가 사라지고, LLM 호출 실패를 보고하기 위해 LLM을 다시 부르는 구조는 실패 상황에서 함께 무너집니다.

## 설계 메모

### 파일 구성

| 파일 | 책임 |
|---|---|
| `tour_recommend.py` | 인자 파싱, 파이프라인 배선, 결과 저장 |
| `gemini_provider.py` | Gemini 호출 계층. 모델 폴백 포함 |
| `prompts/*.txt` | 단계별 프롬프트 템플릿 (`{{입력}}` 자리표시자) |

`tour_recommend.py` 안에서는 역할별로 함수를 나눴습니다.

| 함수 | 책임 |
|---|---|
| `valid_date()` | 입력 경계에서 날짜 검증 |
| `load_prompt()` | 템플릿 로드 및 자리표시자 치환 |
| `run_stage()` | LLM 호출 → 파싱 → 검증 → 재시도 → 저장. 1·3단계가 공유 |
| `search_places()` | Kakao Local 호출 |
| `log_warning()` | 운영 로그 기록 |
| `main()` | 배선과 흐름 제어 |

**분리 기준은 코드량이 아니라 "외부 세계와 닿는 곳"입니다.** 실패하는 곳, 키를 아는 곳, 교체 가능성이 있는 곳이 그곳이기 때문입니다. `gemini_provider.py`를 별도 파일로 뺀 것도 같은 이유이며, 파일 저장처럼 실패 모드가 없는 처리는 `main()`에 두었습니다.

`run_stage()`는 1단계와 3단계가 함께 사용합니다. 두 단계 모두 "프롬프트를 만들어 LLM을 부르고, JSON으로 파싱하고, 필수 키를 검증하고, 실패하면 한 번 재요청한다"는 절차가 같기 때문입니다. 스테이지마다 다른 것(프롬프트 파일, 필수 키 목록)은 인자로 전달합니다.

### JSON 스키마 검증

```python
missing = [k for k in keywords if k not in jsonResult]
```

필수 키 목록을 `run_stage()`의 인자로 받아 **키의 존재 여부만** 확인합니다. 값의 유무로 판정하지 않는 이유는 `events`에 있습니다 — 해당 시기에 행사가 없으면 빈 배열이 정상 응답이므로, `not jsonResult.get(k)`로 검사하면 정상 응답을 실패로 처리하고 불필요한 재요청이 발생합니다.

검증에 실패하면 JSON 파싱 실패와 동일하게 취급합니다. 문법이 깨졌든 키가 없든 "다음 단계에 쓸 수 없다"는 점이 같기 때문입니다.

### 지도 API 교체 범위

Kakao를 Naver 등으로 교체할 때 수정하는 함수는 `search_places()` 하나입니다.

- 반환 타입이 `list[dict]`로 고정되어 있어 호출부는 응답 구조를 모릅니다.
- 실패는 예외로 던지고 기록은 호출부가 담당하므로, 함수가 `errors`나 파일 경로를 알 필요가 없습니다.
- 인증 헤더·엔드포인트·쿼리 파라미터가 모두 이 함수 안에 있습니다.

호출부가 알고 있는 것은 `search_places(city) -> list[dict]`라는 계약뿐입니다.

### 추천 도시의 입력 정규화

추천 도시가 "강원도"처럼 광역 단위로 나오면 장소 검색 결과가 지역 전체에 흩어져 품질이 떨어집니다. 이 프로젝트는 **프롬프트 단계에서 차단**합니다.

```
1. 해당 시기에 여행하기 좋은 국내 도시 1곳을 선정한다.
   - 시/군/구 단위로 지정한다. (예: "강릉시", "경주시", "여수시")
   - 광역시는 구 단위까지 좁힌다. (예: "부산 해운대구")
```

실행 결과에서 `순천시`, `정읍시`, `부산 해운대구`가 반환되어 의도대로 동작함을 확인했습니다.

코드 단계에서 보정한다면 대안은 두 가지입니다. 하나는 Kakao 응답의 `meta.same_name.selected_region`을 확인해 검색어가 어떤 지역으로 해석되었는지 검사하고, 광역 단위로 잡혔으면 대표 도시를 다시 요청하는 방법입니다. 다른 하나는 검색어에 세부 키워드를 덧붙여 범위를 좁히는 방법입니다. 다만 프롬프트에서 막는 편이 API 호출을 늘리지 않아 우선합니다.

### GET / POST

| 호출 | 메서드 | 이유 |
|---|---|---|
| Kakao Local 키워드 검색 | GET | 조회. 같은 키워드는 같은 결과이고 서버 상태를 바꾸지 않음 (멱등·안전) |
| Gemini `generateContent` | POST | 생성 요청. 같은 프롬프트도 매번 다른 결과가 나오고 토큰이 차감됨. 프롬프트 길이가 URL 길이 제한을 넘길 수도 있음 |

길이 제약만이 이유는 아닙니다. GET은 멱등하고 안전하다는 규약 위에서 캐시·프리페치·자동 재시도 같은 중간 계층이 동작하므로, 부작용이 있는 요청을 GET으로 만들면 의도치 않은 재실행이 발생합니다.

두 API 모두 키를 쿼리스트링이 아니라 헤더로 전달합니다(`Authorization`, `x-goog-api-key`).

### LLM 출력을 JSON으로 강제한 이유

자유 텍스트를 받으면 다음 단계에서 도시명을 뽑아내기 위해 문자열 파싱이 필요하고, LLM의 표현이 바뀔 때마다 깨집니다. `responseMimeType: application/json`으로 형식을 강제하고 필수 키를 코드에서 검증하면 2단계 입력이 항상 같은 모양으로 들어옵니다.

부수적으로, 검증 지점이 명확해져 실패를 조기에 잡을 수 있습니다. 자유 텍스트는 "제대로 왔는지"를 판정할 기준 자체가 없습니다.

### 401 / 403 진단

| 상태 코드 | 의미 | 대표 원인 |
|---|---|---|
| 401 | 인증 실패 — 신원 확인 자체가 안 됨 | 키 오타·누락, 헤더 형식 오류(`KakaoAK ` 접두어·공백), 폐기된 키 |
| 403 | 인증은 됐으나 권한 없음 | 플랫폼/도메인 미등록, 해당 API 미활성화, 쿼터 초과 |

디버깅 순서:

1. **키가 실제로 로드되었는가** — `.env` 파일 위치, 값 뒤의 공백·따옴표
2. **헤더 형식이 맞는가** — Kakao는 `Authorization: KakaoAK {키}`, Gemini는 `x-goog-api-key: {키}`. 접두어 대소문자와 공백이 흔한 실수
3. **키 종류가 맞는가** — Kakao는 REST API 키. JavaScript 키·Admin 키는 이 엔드포인트에서 거부됨
4. **콘솔 설정** — 플랫폼 등록, API 활성화 여부
5. **쿼터** — 일일 한도 초과 여부

401은 재시도해도 같은 결과가 나오므로 백오프가 무의미합니다. 이 프로그램이 지도 API 실패에 재시도를 두지 않은 이유이기도 합니다.

### .env를 쓰는 이유

**보안 관점** — 키를 코드에서 분리하면 저장소에 커밋되지 않습니다. 셸 `export`도 동작하지만 전역 환경과 셸 히스토리에 남고, 프로젝트별 분리가 되지 않습니다.

**운영 관점** — 키가 교체되어도 코드 수정 없이 `.env`만 바꾸면 됩니다. 실행 환경(로컬·CI·서버)마다 다른 값을 쓸 수 있고, `.env.example`로 "필요한 키 목록"만 공유해 새 개발자가 재현할 수 있습니다. 이 프로젝트에서는 모델명(`TEXT_MODEL`)도 같은 방식으로 뺐기 때문에, 특정 모델이 장애일 때 코드를 건드리지 않고 전환할 수 있습니다.

## 알려진 한계

- `events`(행사/축제)는 LLM 추론 결과이며 외부 데이터로 검증하지 않습니다. 다른 필드와 달리 실재를 확인할 경로가 없으므로 방문 전 확인이 필요합니다.
- 일정 제안은 맛집 데이터만 참조합니다. 관광지 데이터가 없어 시간대별 활동이 일반적인 서술에 머무를 수 있습니다.
- 리포트 각 섹션의 내부 서술 형식은 프롬프트에서 지정하지 않아 실행마다 달라집니다.
- 캐시는 날짜 기준입니다. 도시 기준으로 맛집을 캐시하면 키 공간이 작고 데이터가 시간에 따라 변하지 않아 히트율이 높지만, 단발 CLI 실행에서는 같은 날짜 재실행이 유일한 반복 패턴이므로 날짜를 키로 선택했습니다.
